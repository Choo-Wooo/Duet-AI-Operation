# 연구 모드

연구 모드는 사용자의 어려운 질문을 두 모델이 함께 구체화하고, 해결안·반례·검증 결과를 주고받으며 답을 개선하는 진행 방식이다. 학술 주제뿐 아니라 설계 판단, 원인 분석, 수학 문제, 복잡한 의사결정에도 사용할 수 있다. JEV는 다음 발언자와 발언 목적을 정하는 사회자 역할을 맡는다.

## 시작과 역할 설정

웹 진행 화면 오른쪽 상단에서 **일시정지 왼쪽의 개발 모드 ▾ / 연구 모드 ▾ 버튼**을 누르고 모드를 선택한다. 선택은 다음 요청부터 적용된다. 실행 중인 턴·승인·입력 또는 미완료 개발 작업이 있으면 변경할 수 없으며, 화면에 이유가 표시된다. 일시정지한 진행을 다른 모드로 변환하는 기능은 아니다.

**역할** 탭에는 **개발 모드 역할**과 **연구 모드 역할**이 함께 표시된다. 같은 설정 표에서 각 역할의 CLI, 모델, effort, 권한, 컨텍스트 한도를 설정할 수 있다. 모드 선택 창의 **역할·모델 설정** 버튼도 이 화면을 연다.

| 연구 역할 | 우선하는 관점 | 함께 지는 책임 |
| --- | --- | --- |
| 탐색자 · `explorer` | 새로운 접근, 구체적인 해결안, 반례를 반영한 수정 | 가정과 검증 방법 제시, 근거에 따라 자신의 제안 수정 |
| 비판자 · `critic` | 숨은 가정, 실패 조건, 반례, 판별 가능한 검증 | 유효한 대안·개선안 제시, 충분한 근거가 있으면 수용 |

두 역할은 동등한 토론자이며 별도 모델 세션을 사용한다. 최초 생성 시 탐색자는 기존 메인 역할, 비판자는 기존 구현 역할의 모델 설정을 이어받는다. 이미 설정한 연구 역할은 덮어쓰지 않는다. 기본 권한은 모두 `read_only`이며 역할 표에서 변경할 수 있다. 조사·실험 도구도 해당 역할 권한과 기존 승인 정책을 따른다. 연구 역할은 삭제하거나 개발 메인 역할로 지정할 수 없다.

프로젝트 폴더에서 CLI로 시작할 수도 있다.

```sh
python3 duet --workflow research --web
```

입력란의 `/workflow`는 현재 선택을 보여 주고, `/workflow research`와 `/workflow development`는 새 요청 전 모드를 선택한다. 기존 `/mode`의 `sprint`, `review`, `deliberate`, `autopilot` 및 **전권 자동 수락**은 별도 설정이다. 연구 모드를 선택했다고 전권 자동이나 JEV가 자동으로 켜지지는 않는다.

## 진행 과정

1. **목표와 조건 확인**: 탐색자가 사용자 요청에서 목표·성공 기준·제약을 정리한다. 사용자만 정할 수 있는 중요한 정보가 빠졌으면 질문과 필요한 이유를 제출한다. 명확한 요청은 불필요한 확인 없이 진행한다.
2. **독립적인 첫 제안**: 탐색자와 비판자가 차례로 같은 목표를 받아 각각 초기 접근을 작성한다. 이 단계의 프롬프트는 상대 초안을 제공하지 않으며 최근 토론을 먼저 읽지 않도록 지시한다.
3. **목적이 있는 토론**: 현재 후보의 중요한 맹점을 검토하고, 반례·계산·조사·실험으로 쟁점을 판별하며 해결안을 수정한다. 대안과 검증된 후보를 기록에 보존한다.
4. **정리와 완료 확인**: 두 모델의 검토와 성공 기준에 연결된 근거를 확인한 뒤 해결안·구체적인 절차·남은 한계를 정리한다. 미해결 상태로 정리할 수도 있다.

모델은 사람이 읽을 설명과 `duet-research` JSON 보고를 함께 반환한다. Duet은 보고의 형식, 후보·쟁점·근거 ID 참조, 성공 기준의 유지 여부를 확인한다. 잘못된 보고가 상태를 일부만 바꾸지 않도록 검증 실패 시 해당 적용을 되돌린다. `DELEGATE`, `STATUS`, `duet-work` 등 개발 제어 지시문으로 연구 흐름을 바꾸지 않는다.

진행 화면의 **연구 진행** 카드에서 현재 목표, 발언자, 발언 목적, 턴 수, 사용자 답변 대기·보류·완료 상태를 볼 수 있다. 상세 토론과 근거는 기존 `DIALOGUE.md`에 이어서 남는다.

## JEV 사회자

**설정 → JEV 오케스트레이션 관제**에서 API 키와 사용 모드를 설정하고 **질문·턴 전달·정체 판단**을 켠다. 공통 판단 확신 기준의 기본값은 **0.8**이다. JEV가 보는 자료에는 현재 목표와 기준, 최신 보고, 후보와 대안, 열린 쟁점, 근거, 최근 진행 이력, 실제 실행 상태, 보완 횟수가 포함된다. 전송 크기를 제한하고 알려진 비밀값을 가린다. API 설정과 비용 설명은 [JEV 관제](jev.md)를 참고한다.

| 선택 | 진행 목적 |
| --- | --- |
| `explore` | 새로운 해결안 탐색 |
| `critique` | 현재 후보의 중요한 가정·반례 검토 |
| `verify` | 쟁점을 판별하는 조사·계산·실험 |
| `revise` | 유효한 비판을 반영한 후보 수정 |
| `reframe` | 목표·제약을 유지한 새로운 접근 |
| `synthesize` | 현재 결과와 한계 정리·최종 검토 |
| `human` | 실제 사용자 판단이 필요한 구체적인 질문 전달 |
| `repair` | 같은 작성자에게 질문·보고 보완 요청 |
| `stop` | 미해결 사항을 정리하고 진행 보류 |
| `abstain` | 판단 보류, Duet의 제한된 기본 진행으로 복귀 |

현재 상태에서 가능한 선택만 제공한다. 정상 보고 다음에는 탐색·비판·검증·수정·재접근·중단 중 선택하며, 완료 준비 조건을 통과했을 때 `synthesize`를 추가한다. 질문을 제출한 턴에는 `human`, `repair`, `verify`, `abstain`만 제공한다. 조사로 해결할 사실이면 검증 턴으로 보낼 수 있고, 질문이 불명확하면 작성자가 보완한다. JEV는 사용자 답변을 생성하거나 권한을 승인하지 않는다. **실제 사용자 질문은 전권 자동에서도 답변을 기다린다.**

`on`은 기준을 통과한 선택을 적용한다. `shadow`는 API 판단을 기록하면서 기본 경로로 진행하고, `off`는 연구 관제 API를 호출하지 않는다. 낮은 확신, `abstain`, API 오류, 꺼진 진행 판단 기능에서도 연구 모드는 동작한다. 기본 경로는 비판 → 검증 → 수정으로 이어지며, 정체 시 재접근하고 완료 조건이 모이면 정리한다. 답이 필요한 사용자 질문은 불확실한 자동 판단으로 해제하지 않는다.

이 관제는 완료된 턴 사이에 실행된다. 실행 중 출력이 잠깐 없다는 이유로 세션을 종료하거나 재시작하지 않는다. 새 사용자 입력·목표 변경·중단·모드 변경으로 오래된 판단은 폐기한다. 판단 대기 중 일시정지했다면 재개 후 현재 상태에서 다시 판단한다.

## 완료 기준과 반복 한도

현재 후보에 대해 두 역할 모두 검토해야 하며, 각각 모든 성공 기준을 `pass`로 평가하고 그 기준을 뒷받침하는 현재 후보의 근거 ID를 연결해야 한다. 열린 질문·미해결 쟁점이 없어야 하고, 정리 턴에서도 이 조건을 유지해야 완료가 된다. 후보를 바꾸면 이전 후보의 검토를 그대로 재사용하지 않으며, 해소했던 쟁점도 새 후보에 맞는 근거가 필요하다.

이 조건은 검토와 근거의 누락을 막는 절차다. 인용의 진위나 실험 결과의 정확성을 독립적으로 증명하는 장치는 아니다. 두 모델의 동의나 JEV의 높은 확신만으로 정답이 보장되지 않는다.

현재 버전에는 다음 한도가 코드에 고정되어 있다.

- 사용자 입력 이후 **수용된 연구 보고 32개**에 도달하면 정리 턴을 추가하고 미해결 상태로 보류한다.
- **8회 연속 근거상의 진전이 없으면** 정리하고 보류한다. 현재 진전 계산은 새로 기록한 결론 있는 근거 또는 기존 쟁점 해소를 사용한다. 초기 목표 정리와 독립 제안도 진전으로 센다. 기본 진행은 4회 정체부터 재접근을 시도한다.
- 한 보고의 형식·질문 보완은 **최대 2회**다. 해결되지 않으면 원인을 남기고 보류한다.

기존 대화 모드의 턴 한도, 실행 예산·시간 한도, 사용자 일시정지·중단도 적용된다. 한도에 도달해 멈춘 상태는 목표 달성을 뜻하지 않는다.

## 기록과 재시작

연구 상태는 프로젝트의 `.duet/state.json` 안 `workflow`와 `research`에 저장된다. 이름을 붙인 세션 저장·불러오기에도 목표, 후보, 쟁점, 근거, 질문, 검토 상태가 함께 포함된다. 재시작이나 불러오기만으로 이전 토론을 다시 실행하지 않으며 새 사용자 입력을 기다린다. 이어서 입력하면 목표·조건에 대한 변경과 질문 답변을 먼저 반영한다.

JEV 기록은 기존 **`.duet/logs/jev/DIALOGUE.md` 한 파일**을 계속 사용한다. 질문·선택지·선택 결과·확신값과 함께 다음 단계를 구분한다.

- **선택·전달 예정**: JEV가 다음 행동을 골랐지만 아직 실행되지 않은 상태.
- **실제 호출 시작**: 모델 어댑터 준비 후 해당 턴을 실행한 상태. 호출 시작은 완료가 아니다.
- **보고 처리 결과**: 반환된 보고의 적용·거절·실패 또는 최신 입력에 따른 보류.

같은 판단 ID로 선택과 후속 실행을 연결한다. JEV를 끈 상태에서도 일반 토론 기록과 연구 상태는 저장된다. 로그 파일을 판단마다 새로 만들지 않으며 누적 파일은 내용에 따라 커진다.

## 현재 구현 범위

두 모델은 기존 CLI 세션과 승인·도구 체계를 사용한다. 독립 제안은 입력 구성과 프롬프트로 상대 초안을 먼저 보지 않도록 한 것이며, 파일 접근을 격리하는 보안 경계는 아니다.

모델은 허용된 도구로 조사·계산을 수행할 수 있다. 연구 전용 병렬 조사 작업판이나 별도 WorkBoard 스케줄러는 이번 구현에 포함되지 않는다. 두 토론 역할의 주된 진행은 한 턴씩 이어지며, 역할 설정의 개발용 병렬 작업 수와 구분된다.
