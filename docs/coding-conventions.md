# 코딩 컨벤션

특정 작업에서 지켜야 할 코딩 규칙을 Markdown으로 등록하고 구현·검토에 적용하는 기능임. 기본은 꺼짐.

## 등록과 적용

1. 웹 **설정 → 코딩 컨벤션**에서 내용을 직접 작성하거나 `.md` 파일을 불러옴.
2. **컨벤션 저장**을 눌러 프로젝트의 `docs/CODING_CONVENTIONS.md`에 저장함. UTF-8 기준 최대 32 KiB이며 파일 불러오기만으로 저장되지는 않음.
3. **새로 시작하는 작업에 적용**을 켜고 작업을 시작함. 다음 작업에 필요 없으면 끄면 됨.

터미널에서 쓰는 프로젝트도 같은 파일을 만들고 `.duet/roles.yaml`의 `settings.coding_conventions_enabled: true`로 적용 가능. 문서가 없거나 비어 있으면 활성화할 수 없으며, 활성 상태에서 읽기에 실패하면 구현을 진행하지 않음.

새 순차·병렬 작업에는 적용 여부, 문서 전체, SHA-256 버전을 고정해 저장함. 이후 설정을 끄거나 문서를 수정해도 진행 중 작업은 처음 규칙을 계속 사용함. 기존 작업의 기준을 교체하려면 작업을 취소한 뒤 새로 시작함. 작업 생성 전의 일반 메인 턴은 현재 프로젝트 설정을 사용함.

## 구현과 검토

- 계획에서 적용 규칙과 검사 방법을 정하고 구현자가 같은 문서에 따라 작업함.
- 컨벤션을 켠 순차 위임은 `sprint`에서도 계획 → 합의 → 구현 → 검토를 거침.
- 검토자는 실제 변경 파일과 검사 결과를 확인하고 규칙별 준수 여부와 근거를 보고함. 기존 린터·포매터·정적 검사 명령이 있다면 계획의 검사 명령에 포함하고 실제 결과를 확인하도록 문서에 적으면 됨.
- 검토 보고가 없거나 문서 버전이 다르거나, `fail`·`unchecked`·빈 근거가 있으면 `ACCEPT`를 막고 보완을 요청함. 병렬 작업의 기존 실패 예외인 `ACCEPT baseline`도 이 검사를 생략하지 못함.
- 컨벤션 검토가 통과해도 기존 테스트·권한·병합 조건을 계속 적용함. 업로드한 문서의 명령은 저장만으로 실행하지 않음.

검토 보고에는 아래 JSON 코드 블록을 하나 포함함. Duet이 모델에게 이 형식을 안내하므로 사용자가 직접 작성할 필요는 없음.

````markdown
```duet-conventions
{
  "sha256": "해당 작업에 고정된 문서의 SHA-256",
  "status": "pass",
  "checks": [
    {
      "rule": "공개 함수는 snake_case를 사용한다",
      "status": "pass",
      "evidence": "src/parser.py:18의 parse_record 이름과 이번 변경 함수를 직접 확인했다"
    }
  ]
}
```
````

문서의 적용 가능한 모든 규칙을 항목별로 확인하도록 지시하며, 적용 대상이 없는 규칙도 이유를 남김. 검토 기록은 순차 작업의 `DIALOGUE.md`, 병렬 작업의 `docs/work/<작업 ID>.md`에서 확인 가능.

임의의 자연어 규칙을 기계적으로 증명하는 기능은 아님. 코드가 강제하는 것은 동일한 문서 버전과 명시적인 검사 보고·근거의 제출이며, 근거의 타당성과 실제 준수 여부는 검토 모델과 실행한 검사 도구가 판단함.

## 작성 예시

```markdown
# 프로젝트 코딩 컨벤션

## 이름과 구조
- Python 함수·변수는 snake_case, 클래스는 PascalCase를 사용한다.
- 파서는 입력을 반환값으로 변환하며 파일·네트워크 I/O를 수행하지 않는다.

## 오류 처리
- 예외를 잡을 때 복구 또는 호출자에게 전달할 이유를 명시한다.
- 비밀값을 오류 메시지와 로그에 남기지 않는다.

## 검토 방법
- 변경한 공개 함수와 예외 처리 코드를 직접 확인하고 파일:줄 근거를 남긴다.
- 프로젝트에 설정된 기존 린터·테스트를 관련 변경에 맞춰 실행하고 명령과 결과를 기록한다.
```
